# E3 analysis implementation audit (read-only)

Scope: `analyze_e3.py`, `curve_stats.py`, `survival.py`, current design/protocol and relevant lab rules. No real experiment statistics were recomputed; prior `analysis.md` and output JSON were not used as evidence. Paths below are relative to `/Users/xuqiluo/PycharmProjects/PII_Extraction`.

## Must fix before a defensible rerun

1. **[P1] Degenerate confidence intervals are still unwired in the headline curve and H2.** `analyze_e3.py:113-123` always uses percentile bootstrap for alpha and tau; `curve_stats.py:215-226` does so again inside `usable_points`. Neither calls `is_degenerate` (`curve_stats.py:258-260`), `wilson_ci_eff` (`263-280`) or `newcombe_diff_ci` (`283-296`). Thus 0/n or n/n can produce a zero-width interval, precisely the failure prohibited by design `676-689` and reporting `38-43`. This feeds false floor certification and zero tau uncertainty at small k. Apply the mechanical 0/n or n/n trigger and Wilson on declared n_eff to each arm; if either arm degenerates, use independent-arm Wilson/Newcombe-MOVER for tau. Preserve bootstrap vectors for curve functionals, but do not substitute degenerate percentile bands for pointwise uncertainty. Record interval method, successes, attempts, unique targets/persons and n_eff per row.

2. **[P1] H2 is decided using the wrong hypothesis, below the declared measurement resolution.** `analyze_e3.py:141-157` calls the carried floor-only condition the governing preregistered form and sets top-level `supported` from any *point estimate* <= 1%. The design explicitly says the joint floor-and-signal criterion governs (`219-221`, `578-598`, `843`), while 1% must be marked unresolved below the achieved resolution. `none_meet.mean()` at `137-150` is merely the bootstrap fraction for the floor event; it neither tests the joint criterion nor repairs all-zero resamples. `ALPHA_MAP` (`23`) supplies mostly sub-resolution tolerances and ends at 10%; the deliverable at `165-176` ignores signal and lacks the separate detection/certification optima required by design `595-598`. Required outputs: carried 1% form as unresolved when unresolvable; joint criterion over declared resolvable tolerances; signal-aware k*; descriptive feasible set and both requested optima; uncertainty-driven absence distinguished from evidence of absence. A 0% observed floor is not certified <=1%.

3. **[P1] Claimed four-test Holm correction is actually three tests, with H4 uncorrected and local verdicts unsynchronized.** `analyze_e3.py:333-337` always supplies NaN for H4; `holm` then discards NaNs and sets m to finite items (`50-55`). Consequently the declared family `{H1,H2,H3,H4}` (`101`, design `858-865`) is shrunk. H4 is scored from an unadjusted 95% interval (`203-218`), while H1 `supported` (`131-132`), H2 `supported` (`151`,`157`) and H3 `reading` (`182-190`) are created before and never reconciled with the corrected decisions. Defining a valid H4 p-value/test and a defensible joint H2 test was not actually completed by the old driver. Keep the fixed family size 4 even for untestable members, and explicitly record any conservative allocation or revised test specification as a deviation; do not quietly drop them. All inferential verdict fields must use the same final decision policy. Also `boot_p_two_sided` (`37-45`) can report literal p=0 from finite Monte Carlo draws; report its resolution/uncertainty rather than interpreting zero as exact.

4. **[P1] `bound_tightness` asserts an unsupported deterministic theorem and interchanges the meanings of the two entropies.** `analyze_e3.py:255-273` invents `k_min(t) >= H(t)/log2|V|` as “Prop. 1 at the target's own self-information,” counts per-target “violations,” and says H(t) governs actual-string forcing. The contract distinguishes reference-model self-information H(t) from format min-entropy H_infinity (`design.md:793-810`); it calls Proposition 1 a probability *upper bound*, which predicts no particular value (`60-62`, also `111`). A probability upper bound is not a hard per-target minimum capacity. Using H(t)/log2V may be a descriptive reference ratio, but it must be labeled exploratory and cannot certify theorem tightness or violations absent an actual derivation. H4's model-conditioned regression is separate from Corollary 1's theoretical format bound.

5. **[P1] Effective n for repeated seeds is inconsistent with the declared clustering design.** `curve_stats.py:33` fixes DEFF=1.5 for two fields, and `wilson_ci_eff` divides its caller's raw count by it (`273`). The actually wired exploratory field analysis passes all seed attempts (`analyze_e3.py:316-323`), hence 3 attempts/person/field with a two-field DEFF. A future naïve main-curve wiring would pass 6 attempts/person with DEFF=1.5. Design `262-269` and protocol `83-88` explicitly distinguish 6 repeats/person at 3 seeds: DEFF=3.5 at ICC=.5 and n_eff=42.9 for 25 persons, not 150/1.5=100. Resolve the contract's older target-only resolution text (`design.md:600-618`) versus later repeated-seed calculation transparently before rerun; expose a declared n_eff/ICC convention and appropriate field-specific repeats, with sensitivity if needed. Do not silently count seed attempts as new persons.

6. **[P1] The analyzer can bypass the evidence contract entirely.** `load` (`analyze_e3.py:29-34`) concatenates any matching parquet files; `analyze` derives the grid/seeds from whatever is present (`95-102`) instead of asserting the planned grid. `main` (`345-350`) runs directly on a glob and never checks `results.json`, completed statuses, dirty-code exclusion, reproducibility check, pins, duplicates, dataset comparability or expected cells. `person_by_k` (`curve_stats.py:46-47`, `57-62`) silently turns missing exact_match into False and weights incomplete cells instead of failing. The raw audit/ledger reconstruction is therefore a necessary external gate; the reanalysis entry point should consume only ledger-linked, eligibility-checked rows and assert their matrix before statistics.

## Missing preregistered outputs / model checks

7. **[P2] H4 secondary specification and diagnostics are absent; the fit ignores some declared gates.** The design promises level-scale censored Tobit with intercept (`738-740`), complete-case linear fit as a censoring comparison (`758-762`), both beta estimators and intercept (`780-791`, success `1109-1112`), and within-field vs between-field H_bits variance (`1056`). `analyze_e3.py:194-218` reports only an AFT and global H min/median/max; `222-253` adds unbootstrapped complete-case ratio summaries, not those missing models. No Tobit/quadratic implementation appears elsewhere in Python sources. `survival.py:107` defaults H4 to 2,000 bootstrap fits, and the caller `analyze_e3.py:203-204` does not pass `n_boot`, despite design `653` specifying 10,000 and CLI advertising `--n-boot`. Censoring >60–70% is only described (`survival.py:80-84`), never triggers the promised Turnbull fallback. `identifiable` at `171` is not enforced by `h4_proportionality_supported` (`164`) or the driver (`206-218`), so even an inadequate surviving-fit set can get a verdict. Also containing 1 denotes non-refutation/compatibility, not an equivalence test proving proportionality; write the exact decision rule and its limitation.

8. **[P2] H5 ignores tied maxima/flatness and omits the preregistered quadratic secondary check.** `curve_stats.py:243-247` uses `np.nanargmax`, which deterministically selects the first maximum, and the point estimate comes from bootstrap means, not the empirical tau curve (`245`). A plateau beginning at an interior k and extending to the last grid point can therefore be called interior because the upper-end tie is discarded (e.g. identical replicate curves `[0,1,1,1]`: first-argmax is the second position even though the maximum includes the last position). A fully flat curve is not explicitly detected/labeled. Design `846` requires a flatness decision and a person-clustered quadratic log-k test of b<0; the entire H5 driver is only `analyze_e3.py:330`. Specify tie-set behavior and flatness, use the observed curve for the point statistic, provide the secondary quadratic coefficient/CI, and retain the exploratory/underpowered label.

9. **[P2] Balance does not produce the two mandatory SMD variants or all covariates.** Design `558-566` and success `1113` require matched-pair and deduplicated marginal SMDs per field, based on E17 matches and covering field/length/tokenization/entropy. `analyze_e3.py:291-300` computes just one achieved-sample marginal variant on H_bits and token length; `306-307` explicitly skips char length and it never reads matches or constructs the pair-weighted variant. The actual attack subset's balance is useful but additional to the two promised match diagnostics. The local SMD helper also reports 0 when pooled SD is 0 (`283-284`), even if means differ; such a degeneracy should be undefined/infinite or explicitly flagged, not marked balanced.

10. **[P2] Anchor, per-arm uncertainty, compute and report-ready fields are incomplete.** The k=0 anchor (`analyze_e3.py:105-110`) lacks its required CI (`design.md:1097-1098`) and no sanity condition blocks on nontrivial control EMR (`841`). Curve rows (`115-123`) contain no trained-arm CI, success counts, unique target count or per-row person count (only a separate global count); there are no per-seed spreads or accelerator-hour/cost fields anywhere in the output. `main` only writes JSON (`351-353`), so producing verified tables/figures plus ledger compute and predictions-vs-outcomes remains separate work. Do not mark the analysis complete merely because this JSON exists.

## Contract conflicts to disclose rather than silently repair

- Design's governing H4 test was revised to log-log slope gamma=1 (`719-740`, `845`), but earlier H4 wording (`174-180`), the two-estimator discussion (`789-791`) and success criterion (`1111`) still call the level-scale intercept the test. Use the explicit revised log-log test for primary H4; retain level Tobit/linear intercept as secondary and record why.
- Design contains a stale precision table label “50 — this study's control arm” (`608`) but explicitly says 25 matched controls (`616-641`); protocol `21`, `35-39` fixes up to25. Do not infer n from prose; raw realized sample and protocol govern.
- Reporting `64` says tables generated by `make_tables.py` alone; current analysis driver instead generates JSON. If a new ledger-driven report generator is used, document that implementation deviation and ensure all numbers flow from the audited ledger.

## Implementations that do match their intended structure

- H1 uses Spearman with person-clustered replicate vectors (`analyze_e3.py:127-132`) and supplies isotonic alpha (`124`), instead of zero-tolerance adjacent monotonicity.
- H4 uses control arm only (`analyze_e3.py:194`), a log-log covariate and interval/right censoring (`survival.py:118-130`), plus person-clustered refits (`133-153`). Non-monotone hit pattern is surfaced (`analyze_e3.py:195-201`).
- k_min excludes the distinct k=0 probe (`analyze_e3.py:66-79`), and achieved-sample balance excludes k=0's differently rendered targets (`286-292`).
- H5 is explicitly marked exploratory and excluded from the stated confirmatory family (`analyze_e3.py:330`).
